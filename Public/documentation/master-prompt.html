# Frame-Generator-API — Master Prompt de Integração (IA / Projetos)

Use este prompt ao integrar o Frame-Generator-API em um modelo de IA,
agente, pipeline ou projeto.

## Identidade e escopo
- Nome: Frame-Generator-API (FGUA) — v2
- Objetivo: núcleo web modular para análise/registro de modelos,
  inspeção de capacidades/recursos e planejamento/integração de fluxos
  de geração e aprimoramento de quadros (imagem, vídeo, jogo) sob um
  contrato lógico (/api/v1/*).
- Runtime: HTML5, CSS3, JavaScript (ES Modules), execução no navegador.
- Hospedagem: GitHub Pages (site estático). Não há servidor REST nativo.
- Interface: shell de sistema operacional Windows 11 (taskbar, Start,
  janelas, Quick Settings) + 12 apps integrados ao núcleo.
- Repositório: https://github.com/kauan11-boop/Frame-Generator-API

## Arquitetura
- src/ (núcleo modular, 10 pastas): core, config, models, runtime, api,
  generators, repacks, security, storage, shell.
- Public/ (interface, 10 pastas): desktop, apps, styles, assets,
  documentation, presets, templates, manifests, locales, workers.
- configs/ (JSON único): api.json, models.json, generators.json,
  repacks.json, permissions.json, settings.json.
- tests/ e scripts/: npm run ci valida tudo.

## Contrato lógico /api/v1
Namespaces: system, models, metadata, quantization, generators, frames,
images, videos, engines, repack, tools, users, permissions, config, jobs,
storage.
Modos: demo (padrão, sem backend), local/remote (baseUrl compatível).

## Capacidades e limites reais (obrigatório respeitar)
- GGUF: análise de metadados no cliente (parser binário, header/KV).
  Carregamento/inferência real requer runtime/provedor compatível.
- Quantização: identificação, estimativa e planejamento; conversão
  efetiva requer runtime externo. Arquivo original preservado.
  Sem conversão fictícia.
- Geração/processamento: planejamento/análise e estados explícitos;
  sem simulação de resultados.
- Engines: detecção WebGPU/WebGL/WASM/WebCodecs, adaptadores TF.js e
  Transformers.js sob demanda (CDN), backend configurável.
- Segurança: autenticação/permissões em nível de UI; autorização
  confiável exige backend; sem segredos em arquivos públicos.
- Jogos: sem interceptação automática de pipeline gráfico; apenas
  integrações/capturas autorizadas.

## Integração recomendada
1. Consumir configs/*.json e o payload de integração do dashboard.
2. Configurar backend/provedor compatível quando for necessária
   execução real (LM Studio: http://localhost:1234 + CORS).
3. Selecionar engine/modelo/provedor conforme formato/operação/capacidades.
4. Tratar estados explicitamente: ready, planned, analyzed,
   requires-provider, requires-runtime, unavailable, invalid, failed,
   cancelled, succeeded.
5. Validar manifests/configs antes de uso e respeitar limites do
   ambiente estático. Verificação: npm run ci.

## LM Studio
- OpenAI-compat: GET /v1/models · POST /v1/chat/completions ·
  POST /v1/completions · POST /v1/embeddings · POST /v1/responses
- REST nativa v1 (0.4+): GET /api/v1/models · POST /api/v1/chat ·
  POST /api/v1/models/load · POST /api/v1/models/unload
- REST v0 (legado): GET /api/v0/models · POST /api/v0/chat/completions
- CORS obrigatório; auth opcional (Authorization: Bearer <token>).
