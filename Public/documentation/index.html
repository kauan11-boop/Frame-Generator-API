Documentação — Frame-Generator-API

Plataforma web modular estática (FGUA) para análise e registro de modelos, inspeção de capacidades/engines/provedores e integração por contrato lógico /api/v1. Hospedagem alvo: GitHub Pages.

Estado real da interface

O dashboard web atual oferece visão geral, inspeção de recursos/capacidades, visualização de registros da sessão (modelos, geradores, tarefas quando existentes), configuração de backend na sessão, exportação de payload de integração e acesso a configurações/documentação/artefatos públicos. Não há fluxos completos de upload/execução/gerenciamento administrativo na UI sem runtime/provedor compatível.

Modos de operação

  • demo (padrão): núcleo local no navegador. Operações remotas retornam indisponibilidade explícita quando não há backend configurado.
  • local / remote: permitem definir URL base de backend compatível (na sessão) para operações que exigem execução externa.

Importante: inferência, quantização efetiva e processamento pesado não são simulados. Estados como unavailable, requires-provider e requires-runtime indicam dependências ausentes.

Contrato e configuração

  • Contrato lógico: configs/api.json (base, mode, backend, namespaces) e ApiController.getContract().
  • Configurações públicas: configs/settings.json, configs/models.json, configs/generators.json, configs/repacks.json, configs/permissions.json.
  • Payload de integração: exportado pelo dashboard com status, capacidades, recursos registrados e referências.

Módulos do núcleo (src/)

  • core: EventBus, ModuleRegistry, LifecycleManager, ApiController, JobManager, ProviderManager, utilitários/contratos.
  • configuration: JsonManager, SettingsManager.
  • models: MetadataLoader (GGUF), ModelLoader, ModelRegistry, ModelCompatibility.
  • quantization: QuantizationAnalyzer, QuantizationManager (análise/planejamento; execução efetiva requer runtime externo).
  • generators: FrameGenerator, ImageGenerator, VideoGenerator, GeneratorRegistry.
  • processing: ImageProcessor, VideoProcessor, FrameProcessor.
  • engines: WebGPUEngine, WebCodecsEngine, ONNXEngine (adapter), BackendAdapter.
  • repacks: ManifestLoader, RepackManager, ToolRegistry.
  • security: AuthenticationManager, PermissionManager, ValidationManager (nível de UI/cliente em ambiente estático).
  • storage: IndexedDBManager, CacheManager, HistoryManager.

Capacidades e limites

  • GGUF: parser no navegador com validações de limites e extração de metadados/tensores (sujeito a tamanho/memória). Carregamento/inferência requer runtime/provedor compatível.
  • ONNX: dependente de ONNX Runtime Web carregado e compatibilidade de modelo/operadores.
  • WebCodecs/WebGPU: detectados quando disponíveis; uso efetivo depende de pipeline/modelo/runtime compatível.
  • Jobs/tarefas: estados explícitos (ex.: pending, queued, running, succeeded, failed, cancelled, unavailable).
  • Segurança: sem fronteira de servidor no frontend estático; não armazenar segredos em arquivos públicos. Autorização confiável requer backend.
  • Privacidade local: análises no cliente usam APIs do navegador e arquivos selecionados/fornecidos no contexto da sessão; informações de hardware podem ser aproximadas ou omitidas pelo navegador.

Recursos públicos adicionais

  • Presets: Public/presets/default-presets.json e configs/settings.json (fontes declarativas; podem diferir em escopo).
  • Template de tarefa: Public/templates/job-template.json.
  • Manifesto de exemplo: Public/manifests/sample-repack.json.
  • Locales: Public/locales/pt-BR.json, Public/locales/en-US.json (base de internacionalização).
