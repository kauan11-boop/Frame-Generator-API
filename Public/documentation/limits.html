Limites reais (obrigatório respeitar)

Estas regras existem para impedir que qualquer integração de IA invente capacidades que o navegador não tem.

GGUF

Análise de metadados no cliente com parser binário e validações de limites (sujeito a tamanho/memória do navegador). O parser do FGUA lê somente o header (magic, versão, KV, tensores) com orçamento de 32 MB — nunca o corpo. Carregamento/inferência real requer runtime/provedor compatível (llama.cpp, LM Studio, WebLLM).

Quantização

Identificação, estimativa e planejamento disponíveis no cliente. Conversão/quantização efetiva requer runtime externo (ex.: llama-quantize). O arquivo original deve ser preservado. Sem conversão fictícia.

Geração/processamento (imagem/vídeo/frames)

Planejamento/análise e estados explícitos; execução real depende de engine/modelo/provedor/pipeline compatível (WebGPU/WebCodecs, TF.js, Transformers.js, runtime externo). Sem simulação de resultados. A cena 3D do app de Desempenho é renderização real de medição — não é "IA gerando quadros".

Engines

Detecção de WebGPU/WebGL/WASM(WebCodecs), adaptadores TensorFlow.js e Transformers.js sob demanda via CDN (estado unavailable quando offline), adapter ONNX Web quando runtime disponível e backend configurável.

Segurança

Autenticação/permissões em nível de UI no cliente estático (guard por namespace no roteador local). Autorização confiável exige backend. Não armazenar segredos em arquivos públicos. Senhas locais usam SHA-256 + salt (não é substituto de servidor).

Jogos

Não afirmar interceptação automática de pipeline gráfico; usar apenas integrações/capturas autorizadas e compatíveis (ex.: captura de janela concedida pelo usuário, APIs oficiais do jogo/engine).

Modo estático (GitHub Pages)

Sem servidor REST no host: em modo demo operações remotas retornam indisponibilidade explícita. Para execução real, configure modo local (LM Studio em http://localhost:1234 com CORS) ou remote (backend compatível).
