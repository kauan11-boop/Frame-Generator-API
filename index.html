Guia rápido

Como o FGUA se encaixa no GitHub Pages.

O GitHub Pages publica arquivos estáticos. Por isso o painel foi desenhado para fazer todo o trabalho útil no navegador e tratar processos locais como extensão opcional — nunca como pré-requisito.

Fluxo recomendado

  1. Abra o painel publicado ou a prévia local.
  2. Use as ferramentas e o playground para tarefas do dia a dia.
  3. Pesquise no catálogo do REA para planejar uma análise.
  4. Execute etapas que exigem processos locais apenas no ambiente de trabalho.

Limites honestos

  • Página estática não inicia processos nem lê arquivos do disco.
  • O sandbox do playground não tem acesso à página nem à rede.
  • WASM é alvo de análise, não um interpretador universal.
  • Dados de exemplo vêm do snapshot versionado, sem segredos.

Atalhos

  • Ctrl K / ⌘ K — busca rápida de seções e ferramentas.
  • Esc — fecha a busca.
  • Ctrl Enter — executa o playground.

Estrutura publicada

  • index.html — interface.
  • mcp.json — manifesto de ferramentas e conteúdos.
  • dashboard/app.js — lógica e ferramentas.
  • dashboard/data/snapshot.json — conteúdo sincronizado.

Integrações e limites

O que funciona

  • Ferramentas de transformação executadas no navegador.
  • Busca local no catálogo de ferramentas do REA.
  • Relatórios com Evidence IDs quando a integração local está presente.
  • Presets e prompts sincronizados no snapshot.

Limites reais

  • GitHub Pages é estático: não hospeda MCP nem executa código.
  • WASM é alvo de compilação, não interpretador de C#/Python/NodeJS.
  • Processos locais exigem o ambiente da máquina do usuário.
  • Primeira execução de modelo exige provedor local ativo.

Nenhum segredo deve ser colocado aqui: o painel é público e o arquivo é versionado.
